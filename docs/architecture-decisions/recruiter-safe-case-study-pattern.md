# Architecture Decision: Recruiter-Safe Case Study Pattern

## Decision

Use a consistent case-study structure across public portfolio documentation: `Overview`, `My Role`, `What This Demonstrates`, `Technical Proof`, `Public Review Context`, and `Confidentiality`.

## Why This Matters

Recruiters and hiring teams scan quickly. A consistent structure lets reviewers compare projects by role, architecture, delivery signals, and confidentiality boundary without reading internal notes or private implementation detail.

## Public Pattern

- Open each case study with a live artifact or public review link where available.
- Add one labeled generated portfolio visual near the top.
- Keep technical proof concise: stack, delivery signals, review checklist, and boundary.
- Avoid fake metrics, fake dashboards, testimonials, or confidential production claims.

## Tradeoff

The format is less dramatic than a marketing case study, but it is more credible for technical hiring review.

## Verification

Each public case study includes exactly one hero visual and one technical proof section, with confidentiality language that speaks to external reviewers rather than internal coaching.
